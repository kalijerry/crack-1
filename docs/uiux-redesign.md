# iOS App UI/UX 改造方案

> 范围：`ios/HPASSApp/HPASSApp/` 的界面层（SwiftUI，iOS 16+）。定位算法（`ios/HPASSKit`）和各引擎的行为不动，只改「怎么呈现、怎么操作」。
> 目标：从「工程师调试面板」变成接近成熟室内导航产品（Apple 地图室内视图、商用室内定位演示 App）的体验，同时保留全部调试能力，收进「开发者」区域。

---

## 1. 现状审查

### 1.1 页面清单（改造前）

| Tab / 入口 | 文件 | 实际内容 |
| --- | --- | --- |
| 门店数据 | `StoreDataView` | 模式开关、地图库、云端地图、价签名单、云端后台、文件状态、服务器下载、文件导入（一页 8 个分区） |
| 地磁定位 | `MagneticView`（1400+ 行） | 顶部地图选择 + 分段「地图 / 采集 / 定位」+ 画布 + 下方长 Form；「实验功能」藏在地图页里；2D/3D/AR 切换叠在画布右上角 |
| 房间扫描（开发模式） | `RoomScanView` | RoomPlan 扫描、结果预览、地图库（重复） |
| 日志 | `LogView` | App 内日志 |
| 采集 / 蓝牙定位（功能开关关闭） | `CollectView`、`LiveLocationView` | 蓝牙指纹采集、蓝牙定位 |
| 二级页 | `AccuracyTestView`、`DataManagerView`、`SessionsView`、`Store3DView`、`AROverlay` | 精度测试、数据管理、历史会话、3D、AR 校对 |

### 1.2 问题

**信息架构**

1. **第一个 Tab 是「门店数据」**：用户打开 App 先看到的是服务器地址、口令、文件导入，而不是地图和自己的位置。
2. **核心功能被塞进一个 Tab 的分段控件**：「地图 / 采集 / 定位」三件完全不同的事共用一个画布和一个 Form，切换时画布上的图层、手势含义（长按 = 放点 / 定点 / 修正）都在变，用户很难建立心智模型。
3. **重复入口**：地图库在「门店数据」和「房间扫描」各出现一次；磁场图信息在三个步骤里各放一份。
4. **日志是一级 Tab**：调试工具和面向用户的功能平级。
5. **开发模式开关埋在「门店数据」第一行**，打开后各页凭空多出几十个控件，没有边界感。

**交互**

6. **调试参数直接暴露**：步行速度、IMU 采样率、磁场可信度、视觉里程计对齐百分比、粒子置信度、`x 1234 y 567 cm` 坐标……普通用户看不懂也不需要。
7. **状态不清楚**：定位状态（搜索中 / 跟踪中 / 丢失）只是一行彩色文字，混在一堆行里；没有统一的「现在是什么状态、我该做什么」。
8. **操作靠隐藏手势**：长按定点、双击设朝向、长按半秒再松手——没有可见的入口，说明写在一大段脚注里。
9. **说明文字过长**：很多 footer 是 3～5 行的段落，信息密度高但没人读。
10. **反馈弱**：开始 / 结束采集、定位成功、到达目的地几乎没有显著的视觉和触感反馈。
11. **画布质感**：蓝点是 12 pt 圆点 + 细箭头，没有朝向锥、没有平滑动画；位置跳变；没有「跟随我」模式；缩放回位按钮是文字按钮。

**术语**

12. 大量内部术语：涂色、贴通道、打底、融合、会话、磁场图、格子数、ARKit 跟踪、粒子滤波……
13. 业务专有词（价签、门店、货架图名、商品条码）不适合通用场景和公开仓库。

**视觉 / 可访问性**

14. 没有统一的颜色、字号、间距，各页随手用 `.green / .orange / .red / .purple`。
15. Canvas 对 VoiceOver 是一整块无名元素；多处固定字号（`.system(size: 10)`）；深色模式下部分灰色对比度不足。
16. 空状态、加载中、出错只有一行灰字或红字。

## 2. 信息架构（改造后）

```
TabView
├── 导航（第一位，面向所有用户）
│   ├── 全屏地图：蓝点 + 朝向锥 + 不确定度圈、跟随 / 自由、楼层切换
│   ├── 顶部：场地 / 地图选择 + 定位状态胶囊
│   └── 底部卡片（按状态切换）：开始定位 → 正在找你 → 已定位（搜索目的地）→ 路线与转向提示 → 已到达
├── 建图
│   ├── 第 1 步 准备：检查清单（地图、权限、手持姿势）+ 可选项
│   ├── 第 2 步 定起点：自动 / 长按地图 → 设朝向
│   ├── 第 3 步 采集中：覆盖率环、本次区域进度、下一段指引、提示胶囊
│   ├── 第 4 步 完成：本次成果（走了多远、覆盖率变化、上传状态）
│   └── 其他建图方式：房间扫描（激光雷达）
├── 地图库
│   ├── 本机地图卡片（在用 / 切换 / 改名 / 删除 / 无线信号开关）
│   └── 云端地图（下载 / 更新）
└── 设置
    ├── 云端连接（地址、口令、自动上传）
    ├── 诊断：精度测试、数据管理、日志
    ├── 开发者模式开关
    └── 开发者（打开后出现）：高级控制台（原地磁页全部功能）、场地数据与导入、蓝牙信标、房间扫描、3D / AR 校对、实验功能
```

原则：

- **一个 Tab 一件事**；同一个手势在同一个 Tab 里含义不变。
- **面向用户的界面只显示结论**（状态、距离、方向、进度百分比），原始数值放进「开发者 → 高级控制台」。
- 旧的调试页面**原样保留**、只换入口和文案，保证开发流程不受影响。

### 改造前后页面结构对比

| 改造前 | 改造后 |
| --- | --- |
| Tab1 门店数据 | Tab4 设置 → 云端连接；开发者 → 场地数据 |
| Tab2 地磁定位 · 地图 | Tab3 地图库（看地图）；开发者 → 高级控制台（点位、朝向、导入） |
| Tab2 地磁定位 · 采集 | Tab2 建图（分步引导） |
| Tab2 地磁定位 · 定位 | Tab1 导航 |
| Tab2 地磁定位 · 实验功能 | 开发者 → 高级控制台 → 实验功能 |
| Tab3 房间扫描（开发模式） | Tab2 建图 → 其他建图方式 |
| Tab4 日志 | 设置 → 诊断 → 日志 |
| 地磁页里的精度测试、数据管理 | 设置 → 诊断 |

## 3. 主要流程

### 3.1 建图采集 → 生成地图 → 定位导航 → 评估

```
[地图库] 选好地图（或下载云端地图 / 扫描房间）
   ↓
[建图] 准备清单全部打勾 → 开始
   ↓  定起点：站着别动自动定位 ／ 长按地图「我在这里」→ 设朝向 → 直走 1.5 m 对齐
   ↓  采集中：跟着橙色箭头走，覆盖率环实时上涨；走太快 / 采样率低时出现黄色提示胶囊
   ↓  结束：成功卡片（走了多远、覆盖率 +x%）+ 触感反馈；自动上传（正常模式）
[云端] 融合生成正式地图 → 地图库自动更新
   ↓
[导航] 开始定位 → 正在找你（沿走廊走 10～20 m）→ 蓝点出现（成功触感）
   ↓  搜索目的地 → 路线 + 转向提示卡片 → 已到达（成功触感）
   ↓
[设置 → 诊断 → 精度测试] 走测试路线，看中位误差和趋势
```

### 3.2 状态模型（导航）

| 引擎状态 | 状态胶囊 | 底部卡片 | 蓝点 |
| --- | --- | --- | --- |
| 未启动 | 灰「未定位」 | 「开始定位」主按钮 + 权限说明 | 无 |
| 搜索中 | 蓝「正在定位」+ 转圈 | 「沿走廊向前走」+ 已用时间 | 无（不乱给位置） |
| 跟踪中 | 绿「已定位 ±1.2 m」 | 搜索目的地 / 路线卡片 | 蓝点 + 朝向锥 + 不确定度圈 |
| 丢失 | 橙「信号弱」 | 「走回已建图区域」+ 手动定位 | 灰点（冻结） |
| 无地图 | — | 空状态：去地图库下载 / 去建图 | — |

## 4. 视觉规范

全部定义在 `DesignSystem.swift`（`DS` 命名空间），新界面只用这里的令牌。

### 4.1 颜色（语义色，自动适配深色模式）

| 令牌 | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| `DS.Palette.accent` | 系统蓝 | 系统蓝 | 蓝点、主按钮、选中态 |
| `DS.Palette.success` | 系统绿 | 系统绿 | 已定位、已完成、覆盖 |
| `DS.Palette.warning` | 系统橙 | 系统橙 | 信号弱、需要注意 |
| `DS.Palette.danger` | 系统红 | 系统红 | 出错、停止、删除 |
| `DS.Palette.route` | 青蓝（#0A84FF→#5E5CE6 渐变） | 同 | 导航路线 |
| `DS.Palette.mapFloor` | `#F2F2F7` | `#1C1C1E` | 地图底色 |
| `DS.Palette.mapObstacle` | `#D1D1D6` | `#3A3A3C` | 障碍物 / 隔断 |
| `DS.Palette.mapCorridor` | 白 | `#2C2C2E` | 可走通道 |
| `DS.Palette.surface` | `secondarySystemGroupedBackground` | 自动 | 卡片 |

所有颜色基于系统语义色或成对定义，深色模式自动切换；状态不只用颜色表达，都带图标和文字（色弱友好）。

### 4.2 字体

只用系统动态字体（`.largeTitle … .caption2`），不写死字号；数字用 `.monospacedDigit()`。

| 令牌 | 样式 | 用途 |
| --- | --- | --- |
| `DS.Typography.hero` | `.title.bold()` + rounded | 大数字（距离、覆盖率） |
| `DS.Typography.title` | `.title3.weight(.semibold)` | 卡片标题 |
| `DS.Typography.body` | `.body` | 正文 |
| `DS.Typography.caption` | `.footnote` | 辅助说明 |

### 4.3 间距与圆角

- 间距 4 pt 网格：`xs 4 / s 8 / m 12 / l 16 / xl 24 / xxl 32`。
- 圆角：小控件 10、卡片 18、底部浮层 24；按钮最小点击区域 44×44。
- 阴影：浮在地图上的元素用 `DS.Shadow.floating`（y 4，半径 12，8% 黑）。

### 4.4 图标

SF Symbols，统一 `.symbolRenderingMode(.hierarchical)`：

| 场景 | 图标 |
| --- | --- |
| 导航 Tab | `location.north.circle.fill` |
| 建图 Tab | `figure.walk.motion` |
| 地图库 Tab | `map` |
| 设置 Tab | `gearshape` |
| 跟随我 / 自由 | `location.fill` / `location` |
| 楼层 | `square.3.layers.3d` |

### 4.5 深色模式

- 地图底色、障碍物、通道全部用成对颜色；蓝点外圈白描边在深色下改为深色描边。
- 浮层统一 `.regularMaterial`，在两种模式下都有足够对比度。

## 6. 地图画布

- **蓝点**：实心蓝点 + 白描边 + 呼吸光晕；朝向锥（扇形渐变，类似 Apple 地图）；不确定度圈半透明填充。
- **平滑动画**：`TimelineView(.animation)` 驱动，位置和朝向按指数平滑插值，避免跳变；定位丢失时变灰。
- **跟随 / 自由**：跟随模式以蓝点为中心、自动放大；用户拖动地图自动切到自由模式；右侧按钮一键回到跟随。
- **楼层切换**：右侧竖排 `FloorSwitcher`，数据来自地图的楼层名；只有一层时显示当前楼层。
- **路线**：渐变粗线 + 白色描边 + 终点旗标；底部 `TurnCard` 显示下一步转向和剩余距离。
- **可访问性**：画布作为一个元素，读出「地图，已定位，精度约 1 米，朝向东北」；所有浮动按钮有标签。

旧的调试图层（涂色、区域、点位、蓝牙粗定位圈等）保持原样，只改配色令牌。

## 7. 文案规范

- 面向通用室内场景：「场地」代替「门店」，「蓝牙信标 / 无线信号」代替「价签」，「障碍物 / 区域」代替「货架」，「位置标识牌」代替「货架黄色标签」。
- 短句、动词开头：「沿走廊向前走」「长按地图：我在这里」。
- 用户界面不出现内部术语：「磁场图」→「地图数据」，「涂色」→「覆盖」，「会话」→「采集记录」，「融合」→「云端生成」。开发者区域保留技术术语。
- **只改显示文字**，不重命名类型、文件、目录（另有计划统一处理）。

## 8. 实现与验收

- 新文件：`DesignSystem.swift`、`AppEngines.swift`、`NavigateView.swift`、`MappingView.swift`、`LibraryView.swift`、`SettingsView.swift`。XcodeGen 的 `sources: - path: HPASSApp` 覆盖整个目录，新文件自动进工程。
- 引擎共享：`AppEngines` 持有唯一的定位引擎和采集引擎，导航、建图、高级控制台用同一份，避免两个页面同时开传感器。
- CI：`ios-app`（xcodebuild）和 `hpasskit` 必须通过。（原来的 `ios-screenshots` 模拟器截图任务已删除。）
