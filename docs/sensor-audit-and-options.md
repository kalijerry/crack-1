# 传感器盘点与可用于导航定位的扩展方案

对象：iPhone 16 Pro + 现有 App（地磁定位页）。「现在用没用」按**代码里实际发生的事**写，不是按设想。

图例：✅ 实时定位里在用　📝 只录进文件、实时定位不用　⛔ 完全没用　— 这台手机或 iOS 不提供

---

## 1. 现状：每个传感器用没用

| 传感器 / 数据源 | 状态 | 现在具体怎么用 | 备注 |
|---|---|---|---|
| 加速度计（DeviceMotion，50 Hz） | ✅ | 计步、运动检测、重力方向 | 融合引擎 `FusionEngine` |
| 陀螺仪（DeviceMotion，50 Hz） | ✅ | 航向积分（航向默认只靠它） | |
| 磁力计（校准后，DeviceMotion） | ✅ | 取 \|B\|、Bz、Bh 三个特征，喂粒子滤波 | 要先有磁场图，且打开「地磁纠偏」才参与 |
| 罗盘航向（用磁力计修正航向） | ✅ 默认关 | 钢货架旁常偏几十度，所以默认不用 | 页面有开关 |
| 磁场精度（`mag_acc`） | 📝 | 只显示「高/中/低」，**没有用来给地磁降权** | 应该用 |
| 原始磁力计（100 Hz） | 📝 | 只写文件。**实时没用它检测系统重新校准造成的跳变** | 建图脚本离线用了 |
| DeviceMotion 姿态四元数 | 📝 | 只写文件；融合引擎自己有一套姿态滤波 | |
| 计步器 `CMPedometer` | 📝 | 只写文件，没和自己的计步交叉校验 | |
| 气压计 `CMAltimeter` | 📝 | 只写文件 | 单层门店用处小 |
| 罗盘 `CLHeading`（含真北） | 📝 | 只写文件 | |
| 设备状态（电池、发热、亮度） | 📝 | 只写文件，**没有在过热时提醒** | |
| 摄像头 + ARKit 视觉里程计 | 📝 | 仅「建图采集」里给位置真值；**实时定位不开** | 最大的浪费 |
| LiDAR 激光雷达 | ⛔ | **完全没用。** 我开 ARKit 时没有打开深度和场景重建，不能说「用了 LiDAR」 | 更正我之前的说法 |
| ARKit 世界地图 `ARWorldMap`（视觉重定位） | ⛔ | 没用 | |
| 摄像头画面识别（招牌文字 OCR） | ⛔ | 没用 | 地图里有 92 个标注，含通道编号牌和部门名 |
| 蓝牙价签 | 📝 / 暂停 | 采集页和「蓝牙定位」页在用；**地磁模式不用**（按你的要求先不用） | 作为后续备用 |
| 运动类型 `CMMotionActivity`（走 / 静止 / 推车？） | ⛔ | 没用 | |
| 超宽带 UWB（U2 芯片） | — | 需要现场装 UWB 基站，不适合 | |
| GPS | — | 室内无信号，只可能用在入口附近 | |
| Wi-Fi 扫描 | — | iOS 不开放 | |
| 环境光 / 邻近传感器 | — | 没有可用的公开接口 / 对定位没意义 | |
| 麦克风 | ⛔ | 不适合（隐私，且对定位没有可靠信号） | |

**一句话：** 现在实时定位只用了「加速度 + 陀螺 + 校准后磁力计」三样，摄像头、LiDAR 和一半的记录项都没进定位。

## 2. 没用上、但对导航定位有用的，逐项评估

| # | 数据源 | 能提供什么 | 提升什么 | 代价 / 风险 | 预期收益 |
|---|---|---|---|---|---|
| A1 | **磁场精度 + 原始磁力计** | 实时识别系统重新校准、磁场不可信的时刻 | 地磁在「磁场不可信」时自动降权，不被带偏 | 小。纯软件 | 中，稳定性 |
| A2 | **CMPedometer 交叉校验** | 苹果自己的步数、步频、距离 | 校正步长、发现漏步 | 小。纯软件 | 中 |
| A3 | **CMMotionActivity** | 区分「走」「静止」「疑似推车」 | 站着时冻结位置；推车时提示精度下降 | 小。纯软件 | 中低 |
| A4 | **磁场全向量**（不只用 \|B\|、Bz、Bh） | 航向可靠后，加入水平分量的方向，信息量大一截 | 区分长度相同的平行通道 | 中。要改地图格式和滤波；对航向误差敏感 | **中高** |
| A5 | **姿态四元数 / 持握分类** | 手持看屏、摆臂、口袋 | 选对步长模型，姿态变化时不误判 | 小 | 中低 |
| A6 | **过热 / 低电量提醒** | 设备状态 | 避免长时间使用后 ARKit 降频 | 小 | 低，但保体验 |
| B1 | **ARKit 视觉里程计（实时）** | 每秒 30 次的相对位移，漂移约行程的 1% 量级（待实测） | **取代计步当运动模型，惯导漂移大幅下降**，地磁只需做纠偏 | 中。耗电发热；要保持摄像头朝前；货架纹理重复可能丢跟踪 | **高，最大的单项提升** |
| B2 | **LiDAR 深度**（`sceneDepth`） | 前方几米内到货架 / 地面的距离（Apple 公开的量程约 5 m，我没实测） | 通道宽度作为「指纹」（每条通道宽度不同）；到左右货架的距离定位通道内横向位置；货架缺口 / 路口作地标 | 中高。要把深度图转成「左右墙距」并与地图货架匹配；货架摆放与地图偏差会影响 | 中高，专治认错通道 |
| B3 | **ARWorldMap 视觉重定位** | 在已扫过的区域，摄像头认出「我在哪」，给绝对位置 | 冷启动和跟丢重定位，不依赖地磁 | **高。** 世界地图是房间尺度，196 m × 92 m 要分很多区、占空间；光照、陈列变化会失效 | 高但不稳，需要先小范围验证 |
| B4 | **招牌 / 通道编号牌 OCR**（Vision） | 读到通道编号牌、部门牌，对应地图标注的位置 | 冷启动、跟丢重定位的绝对地标 | 中。要摄像头对着牌子，悬挂牌子常在头顶；识别率受光线影响 | 中，只在特定位置有用 |
| C1 | 蓝牙价签 | 粗定位 | 冷启动、重定位 | 你要求先不用 | 后续 |
| C2 | 神经网络惯导（RoNIN 类） | 比计步更稳的位移 | 惯导更准 | 高；GPL 许可证；要转 iOS 模型 | 有了 B1 之后收益变小 |
| C3 | 气压计 | 楼层、电梯 | 单层门店没用 | 小 | 低，多层时再做 |

## 3. 打包成方案，供你选

我把能做的拆成四个相对独立的包。**可以多选，建议顺序是 A → B → C → D。** 工期是单人估算，只有 A 我有把握，B、C、D 取决于真机表现。

| 方案 | 内容 | 依赖 | 工期（估） | 主要风险 |
|---|---|---|---|---|
| **A 软件层补齐** | A1 磁场精度降权与实时校准跳变检测；A2 计步器交叉校验；A3 运动类型（静止冻结、推车提示）；A4 磁场全向量（可开关）；A5 持握分类；A6 过热提醒 | 无 | 约 1～1.5 周 | 基本无 |
| **B 视觉里程计进实时定位** | B1：ARKit 作为实时运动模型，与现有粒子滤波融合；丢跟踪时自动退回计步；定点 / 修正时对齐 | 无，但最好先有 A | 约 1.5～2 周 | 耗电发热；货架纹理重复丢跟踪；摄像头一直开的隐私提示（只在本机处理，不存画面） |
| **C LiDAR 通道几何** | B2：深度图转左右货架距离和通道宽度，作为第二路观测；先在离线回放里验证 | 要 B 里的 ARKit 会话 | 约 2～3 周 | 地图货架与实物有偏差；5 m 量程外无效；先要看你真实货架的反射效果 |
| **D 视觉重定位** | B3 世界地图分区重定位 + B4 招牌 OCR；只做冷启动和跟丢恢复 | B 的摄像头会话 | 约 2～3 周，且结果不确定 | 世界地图太大太脆；招牌可见性 |

**我的建议：先做 A + B。** A 便宜且立刻让地磁更稳；B 是最大的收益，把惯导漂移压下来，其他所有方案的效果都建立在运动模型靠谱之上。C 和 D 等 B 的真机数据出来再决定，因为它们是否值得，取决于 B 之后还剩多少误差、主要错在哪。

## 4. 另外：货架偏移的修复（已完成）

你说通道准确、货架偏移。我用数据验证后确认：这份地图是 Konva 风格，**矩形的 (x, y) 是左上角，旋转绕左上角**，而 App 之前按「中心」解释。

| 元素 | 按中心（旧） | 按左上角（新） |
|---|---|---|
| 实体货架 1793 个：通道中心线被压住的长度 | 66 m（68 个货架压到通道） | **0 m** |
| 桌台 430 个：被压住的通道长度 | 331 m（127 个） | **1 m** |
| 虚拟货架 821 个 | 12 m | **0 m** |
| 路径规划：随机 60 条路线 | 全部成功，平均 89 m | 全部成功，平均 88 m |

- 圆形（Circle）和路点（MapRoadPoint）本来就是中心，不动。
- Rect（26 个大块区域）和柱子（2 个）我按 Konva 的惯例也当左上角，**但两种解释下数据都分不出来**，这两类需要你看一眼图上位置是否对。
- 48 个货架旋转 294°，其他全是 0/90/180/270。旋转按「绕左上角、顺时针、y 向下」处理，在这 48 个上同样适用，我没有单独验证它们的位置。
- 这份地图的 `floorOffsetAngle` 是空的，没有「整张图相对正北的偏转」。地图朝向仍然由你第一次「定点 + 设朝向」时记下。
- 代码入口：`StoreDataLoader.loadMap(_:rectAnchor:)`，默认左上角；传 `.center` 可以还原旧行为。
