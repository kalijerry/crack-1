# 开发与打磨路线（2026-10-06 定）

目标：少重复采集、提高精度、后台能实时观察和分析。后台放云端（Cloudflare），门店数据可以上云；会单独采测试会话。

## 阶段 1：评估体系 + 云端后台 + 真机验证（进行中）
- [x] 测试会话：采集页「这次是测试会话」，meta `purpose=test`，不出现在生成磁场图的列表里
- [x] `hpass-eval`：建图会话生成磁场图 + 蓝牙指纹，测试会话冷启动回放，和各自的采集轨迹比（中位 / P90 / ≤1 m / 跳点 / 首次定位距离）
- [x] 云端后台 `server/telemetry`：WebSocket 实时日志和状态、会话 / 地图 / 报告上传、看板
- [x] App：「门店数据 → 云端后台」，日志和状态实时上去，采集结束自动上传会话
- [ ] 部署后台（需要 Cloudflare 账号登录，见 server/telemetry/README.md）
- [ ] 真机验证清单（下面）

已发现：在没采过的区域，冷启动会「定」到别处（建图只有主通道、测试走 1/2 号通道：中位 25 m、跳 5 次）。阶段 3 用蓝牙交叉检验处理。

## 阶段 2：减少重复采集
- 增量建图：每格磁场统计持久化，新会话只追加
- 价签位置从价签数据推出（价签 → 货架 → 地图坐标），全店不采也有蓝牙粗定位
- 采集路线自动规划：一次走完（去程贴一边、回程贴另一边），按段引导
- （分析）双向采集是否必要：比较同一格正反向差异

## 阶段 3：提高精度（每项都用 hpass-eval 验证）
- 三维磁场向量（视觉里程计给出地图系朝向，用东 / 北 / 上三个分量）
- 高斯过程插值代替反距离补齐
- 固定延迟平滑（显示）和前后向平滑（建图）
- 蓝牙与地磁交叉检验：两者持续相差很远就判丢失，防止在没采过的地方误定
- 门店视觉锚点（入口 / 收银台）；LiDAR 横向约束评估后再开

## 阶段 4：长期维护
- 定位即采集（高置信度时低权重并入磁场图，先只记录对比）
- 变化检测（残差热力图，标出要补采的地方）

## 打磨（穿插）
- MagneticEngine 拆分（传感器 / 流水线 / 界面状态）
- 首次使用引导、权限说明、发热省电提示
- 会话质量分，差的会话不参与建图
- 老蓝牙定位页面的去留

## 真机验证清单（下次到店 / 酒店）
1. 地图库：门店 ↔ 房间切换两次，磁场图、点位、涂色各自保留
2. 房间扫描：扫一个房间 → 自动进地图库 → 2D / 3D 正常 → 「自动定位（视觉…）」转一圈能定到，震动
3. 门店采集：用新版沿通道采（蓝牙会一起录）→ 生成磁场图，「磁场图」区块显示蓝牙指纹价签数
4. 门店定位：自动定位，看走多远定到、橙色圈（蓝牙粗定位）在不在附近
5. 测试会话：打开「这次是测试会话」，长按定起点采一段，不参与建图；上传后台
6. 云端后台：部署后连上，看板能看到位置和日志；会话自动上传
