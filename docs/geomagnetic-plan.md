# 地磁为主的室内定位：可行性分析与实施规划

目标：以**地磁指纹 + 惯导（PDR）**为主，**蓝牙价签指纹作为备用**；用 **iPhone 16 Pro** 开启全部可用硬件传感器做完整采集。

> 说明：下文涉及文献精度、传感器速率的数字是业界经验范围，**未在本店、本机上实测**，第 0 阶段的任务就是把它们换成实测值。

---

## 1. 结论

**可行，但要有条件。** 建议立项，用 1 周的低成本实验（阶段 0）先做 go / no-go，再投入开发。

| 判断项 | 结论 | 理由 |
|---|---|---|
| 零售门店有没有足够的地磁特征 | 大概率有 | 钢制货架、冷柜、电机、电梯会造成几十 µT 量级的局部畸变，空间变化大，比空旷建筑更利于指纹区分 |
| 单点地磁能不能定位 | **不能** | 一个采样只有 3 个数，区分度极低。必须用「一段轨迹」做序列匹配，轨迹由 PDR 提供 |
| 纯地磁能不能独立工作 | **不能冷启动** | 平行且对称的货架通道会产生相似的磁信号，需要一个初始位置或粗定位 |
| 预期精度（待实测） | 中位 1～3 m，P90 3～6 m | 文献在结构化建筑里的范围；门店实际取决于货架材质与通道对称性 |
| 最大风险 | 通道歧义、磁场时变、手机自身磁化 | 见第 6 节 |

「地磁为主、蓝牙备用」建议落地成这样的分工，而不是互斥切换：

- **地磁 + PDR**：连续跟踪，提供主要的位置与航向。
- **蓝牙指纹**（现有 `FingerprintPositioner`）：负责**冷启动、跟丢后重定位、地磁置信度低时的兜底**，同时作为粒子滤波的一路弱观测，用来消除通道歧义。
- 地磁置信度和蓝牙置信度都低时，才退回纯 PDR 并向用户提示。

## 2. 现有代码盘点

| 已有 | 位置 | 与本方案的关系 |
|---|---|---|
| 蓝牙指纹定位（高斯似然、WKNN、HMM） | `HPASSKit/Positioning` | 作为备用与重定位，直接复用 |
| PDR：互补滤波姿态、计步、Weinberg 步长、3 状态 EKF、通道约束 | `HPASSKit/Fusion` | 提供地磁滤波的运动模型，复用 |
| 路径规划与导航 | `HPASSKit/Routing` | 不变 |
| IMU 采集（仅 `CMDeviceMotion`，50 Hz） | `MotionRecorder.swift` | **不够**：只有融合后的校准磁场，没有原始磁力计、气压、ARKit 等，需要扩展 |
| 会话格式 v1 | `docs/data-format.md` | 需要向后兼容地扩成 v2 |
| 融合引擎里的磁场使用 | `FusionEngine` 只用磁偏角做航向对齐 | **地磁指纹完全没有**，是新增模块 |

结论：地磁定位是新增 `HPASSKit/Magnetic` 模块，不需要重写现有部分。

## 3. iPhone 16 Pro 全传感器清单

| 传感器 | iOS 接口 | 能否用 | 在本项目里的用途 |
|---|---|---|---|
| 磁力计（原始） | `CMMotionManager.startMagnetometerUpdates` | 是，约 100 Hz | 含硬磁偏置的原始值，用于研究设备自身磁化与校准跳变 |
| 磁力计（校准后） | `CMDeviceMotion.magneticField`（含 accuracy） | 是 | 地磁指纹的主输入 |
| 加速度计 / 陀螺仪（原始） | `startAccelerometerUpdates` / `startGyroUpdates` | 是，约 100 Hz | 计步、姿态；原始值便于离线重算 |
| 融合姿态 / 重力 / 用户加速度 | `CMDeviceMotion`（参考系 `xMagneticNorthZVertical`） | 是 | 把磁场旋转到地球坐标系，提取旋转不变特征 |
| 气压计 | `CMAltimeter` | 是，约 1 Hz，相对高度 | 楼层判断；单层门店可作为环境记录 |

| **LiDAR + 摄像头（ARKit 视觉惯性里程计）** | `ARWorldTrackingConfiguration`，开 `sceneReconstruction` | **是，仅 Pro 机型** | **建图阶段的位置真值**，是本方案最关键的一项 |
| 蓝牙 | CoreBluetooth | 是 | 备用定位与重定位 |
| GPS | CoreLocation | 室内基本无用 | 仅用于门口附近记录 |
| UWB（U2 芯片） | NearbyInteraction | 无锚点则不可用 | 暂不用 |
| Wi-Fi 扫描 | — | **iOS 不开放** | 不可用，这也是蓝牙作为备用的原因之一 |
| 环境光、气压以外的其他传感器 | — | 不开放 | — |

附加记录项：电池、充电状态、`ProcessInfo.thermalState`、屏幕亮度、手机姿态类别（手持看屏 / 摆臂 / 口袋）。这些会影响磁场噪声（充电线、屏幕电流），用于事后分析。

### 3.1 iPhone 特有的两个坑

1. **MagSafe 磁环**：iPhone 16 Pro 背面有永磁体环，保护壳里的磁铁、MagSafe 卡包、车载支架都会直接改变磁场。采集和使用时必须统一配置（建议**裸机或同一个非磁性壳**），并在 `meta.json` 里记录。
2. **校准跳变**：iOS 在后台持续估计磁偏置，`CMDeviceMotion.magneticField` 会在重新校准时发生阶跃。必须同时记录原始磁力计，二者之差就是系统当前估计的偏置，用来检测并剔除跳变段。

## 4. 技术路线

### 4.1 特征：用旋转不变量，而不是原始三轴

手机朝向任意变化，设备坐标系下的三轴值无法直接比对。用姿态把磁场旋转到地球坐标系，再取：

- `|B|`：总强度（与朝向完全无关）
- `Bz`：沿重力方向的垂直分量（只依赖倾角估计，不依赖航向）
- `Bh = √(|B|² − Bz²)`：水平分量大小

三个量都**不依赖航向**，所以不受航向漂移影响。航向可靠之后，再试探加入水平分量的方向（地图坐标系下的 `Bx, By`），信息量更大，但对航向误差敏感，作为第二阶段增强项。

### 4.2 地图：网格化的地磁场

- 栅格 0.5 m（可调），每格存 `|B|, Bz, Bh` 的均值与方差。
- 用走线数据做空间插值（克里金或高斯过程回归），给出每格的不确定度，覆盖不足的区域会被标出来。
- 地图只在**强信号变化区**有定位价值，所以要同时输出「可区分度地图」，告诉你哪些通道定位会差。

### 4.3 在线定位：粒子滤波

```
状态 (x, y, 航向偏差, 步长比例)        N ≈ 500～2000 个粒子
  预测：  PDR 步长与航向（复用 FusionEngine），加噪
  约束：  通道几何（复用 FusionCorridorMap），粒子穿墙则降权
  更新 1：地磁   最近 L 步（约 5～15 m）的 (|B|, Bz, Bh) 序列 vs 地图，高斯似然
  更新 2：蓝牙   FingerprintPositioner 的位置/置信度，宽方差弱观测
  重采样 + 跟丢检测（有效粒子数低、似然持续低）→ 触发蓝牙重定位
```

要点：

- 地磁更新使用**一段窗口**而不是单个采样，窗口内的位移由 PDR 给出。
- 蓝牙观测方差故意放大，只用来打破对称歧义和重定位，不压过地磁。
- 输出位置、航向、不确定度，以及「当前主要依赖哪一路」的标志，用于 UI 和日志。

### 4.4 建图用的位置真值：ARKit + 已知点

走线建图需要每个磁场采样对应的地图坐标。手工打点太稀，PDR 自己建 PDR 的图会累积误差。方案：

- 采集时同时开 ARKit 世界跟踪（LiDAR 辅助），得到 60 Hz 的 6 自由度位姿。
- 每条走线从**已知指纹点 / 货架角**起步，途中经过其他已知点，用这些锚点对 ARKit 轨迹做分段刚体对齐，吸收漂移。
- 货架通道纹理重复，ARKit 可能漂移，所以走线要短（单条 ≤ 100 m）、锚点要密。
- ARKit 只在建图和评测时开，**运行时不用**（耗电、占摄像头）。

## 5. 分阶段计划

按单人开发的粗略工期，仅供排期参考。

### 阶段 0：可行性实验（约 1 周，决定是否继续）

只做采集和离线分析，不写定位算法。

1. 在 16 Pro 上先用现有 App 外加最简原始磁力计记录，选 2～3 条代表性通道（含对称通道、靠近冷柜的通道）。
2. 每条通道往返走 **3 遍以上**，分**至少两天、不同时段**（补货前后、人流多/少）。
3. 离线分析并出报告：
   - **空间变化 vs 噪声**：沿通道 `|B|, Bz` 的标准差，相对同一位置多次通过的差异。
   - **时间稳定性**：隔天 / 隔时段的均方根差。
   - **可区分度**：用其中一遍做地图，其余做测试，跑简单序列匹配（DTW），统计走对通道的比例。
   - **姿态鲁棒性**：手持看屏、摆臂、略低头，三种姿态下特征是否一致。
   - **MagSafe 影响**：同一路线带壳与裸机对比。
4. **go 标准（建议）**：空间标准差 ≥ 重复通过差异的 3 倍；留出遍的通道识别率 ≥ 90%；隔天重复差异没有系统性偏移。不满足则降级为「蓝牙为主、地磁辅助」，工作量大幅下降。

### 阶段 1：全传感器采集器（约 1 周）

在 `ESLCollector` 的 `Recorder` 上扩展，格式向后兼容 v1：

| 新文件 | 内容 | 频率 |
|---|---|---|
| `mag_raw.csv` | 原始磁力计 xyz | ≈100 Hz |
| `motion.csv` | DeviceMotion：姿态四元数、重力、用户加速度、校准磁场 + accuracy、航向 | ≈100 Hz |
| `acc_raw.csv`, `gyr_raw.csv` | 原始加速度、陀螺 | ≈100 Hz |
| `baro.csv` | 相对高度、气压 | ≈1 Hz |
| `pedometer.csv` | 步数、距离、步频 | 事件 |
| `heading.csv` | CLHeading：磁航向、真航向、精度、原始 xyz | ≈事件 |
| `arkit_pose.csv` | 位姿 4×4 或平移+四元数、追踪状态、对齐用的世界原点 | 30～60 Hz |
| `ble.csv`, `marks.csv` | 保持不变 | — |
| `device.csv` | 电池、充电、热状态、屏幕亮度、姿态类别（手动标注） | ≈1 Hz |

要点：

- 所有时间戳统一成 Unix 毫秒，沿用 `systemUptime` 到 epoch 的换算（现有 `MotionRecorder` 已这样做；ARKit 的 `frame.timestamp` 也是开机时间基，同样换算）。
- 蓝牙回调没有硬件时间戳，抖动几十毫秒，对分钟级对齐无影响。
- App 内加一个「采集质量」面板：各路传感器实时速率、磁场精度、ARKit 追踪状态，缺任何一路就醒目告警。
- 每次会话在 `meta.json` 里记录：保护壳、MagSafe 附件、手持姿态、天气温度、门店是否营业。

### 阶段 2：建图流水线（约 1.5 周）

- 采集协议：覆盖所有通道，每条通道**至少 2 遍、方向相反**；每遍起止踩锚点。营业与非营业各采一批以测试稳定性。
- Python 工具 `tools/magmap.py`：读会话 → 剔除校准跳变与低精度段 → ARKit 轨迹对齐到地图 → 旋转到地球系并提取三个特征 → 栅格化 / 插值 → 输出 `magmap.json`（含不确定度与可区分度图）。
- 单元测试：用合成磁场地图 + 仿真轨迹验证建图与插值精度（沿用 `tools/tests` 的做法）。

### 阶段 3：定位算法（约 2 周）

在 `HPASSKit` 新增 `Magnetic/`，纯 Foundation，沿用现有的单位与线程约定：

| 文件 | 职责 |
|---|---|
| `MagneticMap.swift` | 栅格地图的加载、双线性查询、不确定度、可区分度 |
| `MagneticFeature.swift` | 倾角补偿、特征提取、低通与野值剔除、校准跳变检测 |
| `MagneticParticleFilter.swift` | 粒子滤波：预测、通道约束、地磁与蓝牙更新、重采样、跟丢检测 |
| `MagneticPositioner.swift` | 对外接口，与 `FusionEngine` / `FingerprintPositioner` 对接，输出位置、航向、置信度、数据源标志 |

测试：先全部用合成数据在 `swift test` 里验证（粒子收敛、对称通道歧义处理、跟丢重定位），再接真数据回放。

### 阶段 4：App 集成与离线回放（约 1 周）

- `LiveLocationEngine` 增加定位模式：**地磁为主 / 蓝牙为主 / 仅 PDR**，运行时可切换，便于现场对比。
- 实时定位页：叠加地磁热力图、粒子云、当前依赖的数据源、地磁置信度；参数区可调粒子数、窗口长度、观测方差。
- 日志页记录模式切换、跟丢、重定位事件。
- 做一个**会话回放**入口：用采集的会话数据离线重跑算法，所有调参都在回放里做，不必每次去现场。

### 阶段 5：评测与加固（约 1.5 周）

- 评测：沿已知路线行走，用 ARKit 轨迹或打点作真值。指标：位置误差 CDF（中位、P90、最大）、通道判对率、冷启动收敛所需步行距离、跟丢次数与恢复时间。
- **消融对比**：蓝牙 + PDR（现有基线）/ 地磁 + PDR / 地磁 + PDR + 蓝牙。
- 时间稳定性：1 周、1 个月后重走，看是否要重建图，并定下**重采策略**（例如每次大规模补货或调整货架后局部重采）。
- 其他设备：用 S25+ 走同一路线，量化跨机型差异，决定是否需要「磁力计偏置 / 灵敏度标定」。

总计约 8～9 周；阶段 0 不通过，可止损在 1 周。

## 6. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 平行对称通道磁信号相似 | 走错通道、位置跳变 | 蓝牙弱观测打破对称；通道约束；窗口加长；对低可区分度区域降低置信度并提示 |
| 磁场时变（补货、移动货架、推车、冷柜启停） | 地图过时，精度缓慢下降 | 阶段 0/5 实测稳定性；采营业/非营业两批；定期局部重采；粒子滤波对野值用重尾似然 |
| iOS 校准跳变 | 窗口内特征突变 | 同时记录原始磁力计，检测并丢弃跳变段；accuracy 低时降低地磁权重 |
| MagSafe / 保护壳 / 配件 | 与建图时的磁场不一致 | 规定使用配置，写入 meta，必要时标定硬磁偏置 |
| 手持姿态多变 | 倾角估计误差影响 `Bz` | 优先 `|B|`；`Bz` 用姿态质量门控；评测中覆盖多种姿态 |
| PDR 漂移 | 窗口内位移不准，影响序列匹配 | 窗口不宜过长；航向由互补滤波 + 通道约束约束；把步长比例作为滤波状态 |
| ARKit 在重复纹理通道漂移 | 建图坐标不准 | 短走线 + 密锚点 + 分段对齐；对齐残差作为质量指标，超限的走线丢弃 |
| 冷启动无位置 | 初期输出不可信 | 用户点击确认 / 蓝牙粗定位 / 入口先验；收敛前明确标记「定位中」 |
| 电池与发热 | 长时间运行降速 | 运行时只开 100 Hz 的磁力计与 DeviceMotion 和蓝牙；ARKit 仅建图时开 |
| 仅在 16 Pro 上建图 | 其他手机偏差 | 阶段 5 量化，按需增加标定步骤；图本身在 16 Pro 上建，用 16 Pro 使用最稳 |

## 7. 已确认的前提与由此带来的调整

| 项 | 确认结果 | 对方案的影响 |
|---|---|---|
| 精度 | 目标 **1 m**，通道级也可接受 | 把目标分档（见下），1 m 作为冲刺目标而不是通过线 |
| 门店 | 钢货架为主，13000 m² | 磁特征丰富是有利的；但面积大，歧义风险随面积上升（见下） |
| 测试区 | **100 m²**，不全场扫描 | 阶段 0～3 全部在测试区内完成，工作量大幅下降 |
| 用户 | 内部测试，手持看屏 | 姿态最稳定，最有利；暂不考虑口袋、摆臂和多机型 |
| 采集时间 | 可在营业时间进场 | 直接带人流与推车干扰，更接近真实，同时要多采几个时段 |

**精度分档（建议的验收口径）**

| 档位 | 指标 | 说明 |
|---|---|---|
| 通过 | 通道判对率 ≥ 95%，中位误差 ≤ 2 m | 可行性成立 |
| 目标 | 中位误差 ≤ 1.5 m，P90 ≤ 3 m | 大概率靠地磁 + PDR + 蓝牙的组合达到 |
| 冲刺 | 中位误差 ≤ 1 m | 在 100 m² 小区域内有机会；要推到 13000 m² 全场没有把握 |

**关于 Oriient 的对比**：它对外宣称的精度很高，但其算法、地图构建流程与使用条件（定制采集、反复校准）并不公开，不能直接当作本方案的预期。1 m 中位在小范围内可争取，但 P90 与全场一致性要看实测。

**100 m² 测试区的一个陷阱**：只在 100 m² 内做地图并测试，歧义问题被**低估**了，因为全场 13000 m² 里还有大量相似的通道。应对：

- 测试时**不给初始位置**，让算法从全区冷启动，用「收敛到正确位置所需的步行距离」衡量。
- 阶段 0 里另外多走 3～5 条**测试区之外**的通道，只记录磁场，作为「干扰项」放进地图里混淆，检验是否会被误匹配。
- 评估报告中单独给出「若放大到全场，歧义概率」的外推（用可区分度图统计相似窗口的数量）。

**地面真值方案（1 m 精度需要更准的真值）**：测试区的地砖或货架边线是现成的坐标网。先在地面每 1 m 贴标记（或利用地砖缝），走线时在每个标记处打点（现有「打点」功能，约 3 秒即可），真值误差 < 0.2 m。ARKit 位姿留到建图阶段再接。

**营业时间采集要点**：同一条路线分别在人少和人多时走；记录推车、冷柜启停等事件（在 `setup_note` 里写或在日志页备注）；不要为了避开人流而绕路，被挡住就停下来在原地打点。
