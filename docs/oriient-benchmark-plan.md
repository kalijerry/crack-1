# 对标 Oriient 的地磁定位：规划与开发路线

目标：在你的真实门店地图上，做出接近 Oriient 的室内定位（公开宣称约 1 米），手机用 iPhone 16 Pro，蓝牙价签指纹作为备用。

> 说明：Oriient 的算法和流程不公开，下面对它的描述来自官网和公开报道。精度、工期都是**事前估计**，每个阶段末尾的验收门槛会把估计换成实测。

---

## 1. 先把「对标」说清楚

### 1.1 Oriient 公开可知的做法

| 环节 | Oriient 的做法 | 对我们意味着什么 |
|---|---|---|
| 建图 | 派人拿普通手机把店走一遍，记录磁场，只做一次 | 我们也要「走一遍」，但要有**位置真值**，见第 5 节 |
| 定位 | 实时磁场读数 + 手机运动传感器，与磁场图匹配 | 与我们现在的路线相同（惯导 + 磁场图 + 粒子滤波） |
| 地图维护 | 所有用户的传感器数据持续回传，自动刷新地图 | 这是它真正的护城河，第 6 阶段才做 |
| 设备 | 不同手机都能用 | 先只做 16 Pro，多机型放最后 |
| 基础设施 | 不装信标、不依赖 Wi-Fi | 一致 |

### 1.2 我们要达到的指标

| 档位 | 通道判对率 | 位置误差 | 冷启动收敛 | 说明 |
|---|---|---|---|---|
| **通过** | ≥ 95% | 中位 ≤ 2 m，P90 ≤ 4 m | ≤ 40 m 步行 | 可行性成立 |
| **目标** | ≥ 98% | 中位 ≤ 1.5 m，P90 ≤ 3 m | ≤ 25 m 步行 | 内部测试可用 |
| **对标** | ≥ 99% | 中位 ≤ 1 m，P90 ≤ 2.5 m | ≤ 15 m 步行 | 接近 Oriient 宣称 |

「通道判对率」指定位点落在正确通道上的比例。你的长通道间隔约 3.6 m，定位误差超过 1.8 m 就可能判到隔壁通道，所以它比平均误差更重要。

## 2. 你的地图：我读出来的事实

> 以下只是统计数字，没有写任何编码、名称或坐标。地图文件本身不进仓库。

| 项 | 数值 | 对定位的意义 |
|---|---|---|
| 尺寸 | 196 m × 92 m（约 18000 m²） | 全图磁场格子（0.5 m）约 7.2 万个，手机内存没压力 |
| 货架 | 2614 个，其中约 817 个编码为 `Virtual-Shelf` | 虚拟货架不是实体，**要确认**是否参与碰撞和磁场分析 |
| 通道 | 160 条中心线，总长约 3067 m（纵向 2068 m，横向 996 m），宽度多为 140 cm | **这是最大的利好**：人只在通道里走，位置可以降成「在哪条通道的哪个位置」 |
| 交点 | 约 300 个 | 天然的路口锚点，建图和重定位都用得上 |
| 路点 | 1431 个 `MapRoadPoint`，带所属通道编码 | 现成的路网节点 |
| 长通道 | 47 条 ≥ 30 m；43 条纵向通道 > 28 m，相邻间距中位约 3.6 m | **最大的风险**：其中 27 条长度几乎一样（约 33 m），平行、相似 |
| 标注 | 92 个，含部门名称（园艺、地板、照明、卫浴、五金、木材等）和通道编号牌 | 部门是地磁特征差异大的天然分区；入口、扶梯、收银如果有标注，是强地标 |
| 解析 | 外面包着 `{code, message, success, data}` 信封 | **已修复**：原先解析器读出 0 个货架。修好后 46 ms 读完，路径规划 30/30 成功 |

从这些数字得到的判断：

1. 门店是大型建材 / 家居类卖场。钢货架、木材、金属建材都多，磁场起伏通常很大，**对地磁有利**。
2. 通道是长直通道、平行、长度相近。**地磁最大的问题不是精度，而是认错通道**。这决定了算法必须带路网约束、用较长的序列做匹配，并且需要一个粗定位（蓝牙或用户点选）打破对称。
3. 推车是这类门店的常态，推车的金属框架会改变手机附近的磁场。第一期只测手持，推车放到后期单独评估。

## 3. 技术方案

### 3.1 总体结构

```
iPhone 16 Pro 传感器
 ├─ 加速度 + 陀螺 ──→ 惯导 PDR（步数、步长、航向）
 ├─ 磁力计 + 姿态 ──→ 旋转不变磁特征（|B|, Bz, Bh）
 ├─ 气压计 ─────────→ （单层，仅记录）
 └─ 蓝牙价签 ───────→ 备用：粗定位 / 冷启动 / 重定位
                              │
地图（货架 + 通道 + 路点） ───┤
磁场图（建图得到）  ──────────┤
                              ▼
        路网约束的粒子滤波（核心）
        状态：(通道, 沿线位置, 横向偏移, 航向偏差, 步长比例)
                              │
                              ▼
      位置 / 朝向 / 不确定度 / 置信度 / 数据源 ──→ 导航（A* 路径 + 转向提示）
```

### 3.2 关键技术选择与理由

| 问题 | 选择 | 理由 |
|---|---|---|
| 位置怎么表示 | **路网图上的一维位置** + 通道内的横向偏移，而不是整张图的二维自由空间 | 通道总长 3 km，自由空间有 1.8 万 m²。降维后歧义大幅减少，粒子数也可以少 |
| 磁特征 | 先用 `|B|`、`Bz`、`Bh`（与朝向无关）；航向可靠后再加入水平分量的方向 | 不受手持姿态和航向漂移影响，已经在 App 里实现 |
| 观测怎么用 | 沿通道取 10～20 m 的特征**序列**做匹配，而不是单个采样 | 单个采样信息量太少。序列匹配是文献里的共识（Kok & Solin 的磁场 SLAM 也是把过去读数当一维轨迹） |
| 航向 | 陀螺积分为主；**曼哈顿世界先验**：通道基本沿 0°/90° 方向，直行一段后把航向轻拉回通道方向 | 你的货架旋转角几乎全是 90°/270°，通道轴对齐，这是强约束，比罗盘在钢货架旁可靠 |
| 步长 | 在线学习个人步长系数；到达已知路口时用路口间距反推 | 步长误差是惯导漂移的主要来源 |
| 冷启动 | 粒子撒满整张路网，窗口走 15～30 m 收敛；蓝牙粗定位给先验；也允许用户点选起点 | 地磁无法单独冷启动，这就是「蓝牙备用」的用处 |
| 跟丢 | 有效粒子比低 / 似然持续低 → 提示，用蓝牙或长按修正重定位 | 必须有，否则一次走错通道就永远回不来 |
| 地图格式 | 沿通道 0.25 m × 横向 0.5 m 栅格，带标准差和覆盖标记；空间插值用克里金 / 高斯过程 | 比现在的 0.5 m 方格更贴合通道结构 |

### 3.3 可借鉴的开源工作

| 项目 | 取什么 |
|---|---|
| [1d-magnetic-field-slam](https://github.com/manonkok/1d-magnetic-field-slam/)（MIT） | 一维磁场序列 + 回环检测纠偏；**第 6 阶段**做地图自动维护时参考 |
| [Scalable Magnetic Field SLAM](https://arxiv.org/pdf/1804.01926) | 高斯过程磁场图 + 粒子滤波，建图精度的升级方向 |
| [RoNIN](https://github.com/Sachini/ronin)（GPL-3.0） | 神经网络惯导。第一期不用，因为许可证和转 iOS 模型都有成本 |
| [Anyplace](https://github.com/dmsl/anyplace)（MIT） | 整体架构参考：采集端、地图服务、导航端的拆分 |
| MagPIE、UJIIndoorLoc-Mag 数据集 | 公开的真实手机磁场轨迹，可以先离线验证算法，不必每次进店 |

## 4. 开发路线（共 7 个阶段，约 10～12 周，单人）

每个阶段有**产出**、**验收门槛**、**需要你做的事**。门槛不过不进下一阶段。

### 阶段 0：地基与可行性（第 1 周）

| 任务 | 产出 |
|---|---|
| 0.1 地图接入（信封解析已修复） | App 能读你的真实地图；回归测试已加 |
| 0.2 App 大图渲染：缩放、平移、货架 / 通道 / 标注分层，点按选点 | 在手机上看清整张图 |
| 0.3 地磁页改为使用门店地图（现在只认 10×10 m 的小图） | 同一份地图两种模式共用 |
| 0.4 **现场采集 3 条通道**：2 条相邻、长度约 33 m 的平行通道 + 1 条靠近钢货架或冷柜的通道，每条往返 3 遍，分营业和非营业两个时段 | 采集数据（用现有的全传感器采集器） |
| 0.5 跑 `tools/mag_feasibility.py` | **go / no-go 报告** |

**门槛 G0**：空间标准差 ≥ 重复噪声的 3 倍；相邻平行通道之间磁特征能区分（10 m 窗口找回率 ≥ 90%）；隔时段差异没有系统性偏移。
**不过怎么办**：改成「蓝牙为主、地磁辅助」，后面的工作量大幅减少。
**你要做**：进店 0.5 天，在 3 条通道地面贴标记（两端 + 每 5 m 一个），每个标记处打点。

### 阶段 1：建图采集工具（第 2～3 周）

在 App 里加「建图采集」模式，目标是让一个人高效、可靠地走完全场。

| 任务 | 说明 |
|---|---|
| 1.1 引导采集 | 选一条通道 → 屏幕引导沿通道走 → 到路口点「到达」锚点。锚点来自地图的约 300 个交点，不用手贴标记 |
| 1.2 位置真值 | 采集时同时开 **ARKit + LiDAR**（16 Pro 有），记录 60 Hz 位姿。通道内用它给位置，用路口锚点分段校正漂移 |
| 1.3 会话格式 v3 | 在 v2 基础上加 `arkit_pose.csv`、`anchors.csv`（锚点 ID、时间、地图坐标） |
| 1.4 覆盖看板 | 地图上给每条通道上色：未采 / 单向 / 双向 / 已通过质检 |
| 1.5 现场质检 | 走完一条通道立即提示：磁场精度是否一直是「高」、ARKit 是否一直正常跟踪、有没有校准跳变 |

**门槛 G1**：单条 33 m 通道往返采集 < 5 分钟；通道内位置真值误差 < 0.3 m（用已知标记检验）。
**你要做**：16 Pro 上跑一遍，确认 ARKit 在货架通道里不丢跟踪（重复纹理是已知的弱点）。

### 阶段 2：建图流水线（第 3～4 周）

离线 Python 工具 `tools/magmap.py`：

1. 读会话，剔除 iOS 校准跳变和低精度段（用原始磁力计与校准磁场之差判断）。
2. ARKit 轨迹按锚点分段对齐到地图坐标。
3. 旋转到地球系，提取 `|B|`、`Bz`、`Bh`。
4. 沿通道栅格化，空间插值，输出 `magmap.json`（沿用 App 已有的 `magField` 格式并扩展）。
5. **质检报告**：每条通道的覆盖率、重复性 SNR、**可区分度热力图**、最相似的通道对清单。

可区分度热力图是这一阶段最有价值的产出：它在做任何定位算法之前，就告诉你全场哪些地方会认错。

**门槛 G2**：全场每条通道 SNR ≥ 3；报告里的高风险通道对数量有明确清单。
**你要做**：全场建图采集，约 6～8 个工作日，分区进行（见第 5 节）。可以与阶段 3 并行。

### 阶段 3：定位算法（第 4～7 周，核心）

在 HPASSKit 的 `Magnetic/` 里做路网约束的粒子滤波：

| 文件 | 内容 |
|---|---|
| `RoadGraph.swift` | 由通道和路点建图：边 = 通道，点 = 交点；每个粒子站在「某条边的某个位置」上 |
| `GraphParticleFilter.swift` | 预测：沿边前进，到路口按航向变化选分支；更新：序列似然，Student-t |
| `HeadingModel.swift` | 陀螺积分 + 曼哈顿先验 + 用户设定的初始朝向 |
| `StepLengthLearner.swift` | 在线学习步长系数 |
| `RelocationManager.swift` | 冷启动、跟丢检测、蓝牙粗定位注入、用户长按修正 |
| `ReplayHarness`（测试） | 读 CSV 会话离线重跑，输出误差分布和通道判对率 |

**门槛 G3**（回放评测，用阶段 0、1 采到的数据）：通道判对率 ≥ 95%，中位误差 ≤ 2 m，冷启动 ≤ 40 m 步行收敛。
**关键设计约束**：所有调参都在回放里做，不靠现场试。

### 阶段 4：App 与导航（第 6～8 周，与阶段 3 后半并行）

| 任务 | 说明 |
|---|---|
| 4.1 三种模式 | 蓝牙定位 / 地磁定位 / 融合，现场可切换对比 |
| 4.2 导航 | 接真实路网：`RoutePlanner` 已验证 30/30 路线成功；加转向提示和到达判定 |
| 4.3 现场工具 | 长按修正位置、双击设朝向（上一版已有）、一键「我跟丢了」重定位 |
| 4.4 数据导出 | 每次定位的轨迹、特征、修正记录导出，用于回放和复盘 |

### 阶段 5：全场评测与加固（第 8～10 周）

| 项 | 做法 |
|---|---|
| 评测路线 | 10 条，每条 200～400 m，双向，营业和非营业各走一遍 |
| 真值 | ARKit 轨迹 + 路口锚点 + 地面标记 |
| 消融 | 蓝牙 + 惯导（现有基线）/ 地磁 + 惯导 / 地磁 + 惯导 + 蓝牙 |
| 时间稳定性 | 1 周后复测，看补货和人流是否让地图过期 |
| 姿态 | 看屏、略倾斜、摆臂三种 |
| 推车 | 单独评估（金属框架干扰） |

**门槛 G5**：达到「目标」档（通道判对率 ≥ 98%，中位 ≤ 1.5 m，P90 ≤ 3 m）。

### 阶段 6：地图维护与扩展（第 10 周起，可选）

对标 Oriient 的持续刷新能力：

- 定位轨迹本地汇总后回传，用残差统计检测磁场图漂移（补货、货架调整）。
- 增量更新受影响的通道，并参考一维磁场 SLAM 做回环纠偏。
- 多机型：磁力计偏置和灵敏度归一化，再加 Android 端。

## 5. 全场建图的采集方案（具体）

| 项 | 数值 / 做法 |
|---|---|
| 总工作量 | 通道中心线 3067 m，双向 6134 m。纯步行约 1.7 小时，加上锚点、ARKit 重启、休息，实际 **4～6 小时 / 轮**，分 3～5 次完成 |
| 分区 | 按部门分 6～8 个区，每区一次采完，区边界选在路口，便于锚点对齐 |
| 路线 | 先走所有长纵向通道（共 2068 m），再走横向通道 |
| 方向 | 每条通道双向各一遍。方向不同，手持姿态和身体遮挡带来的偏差不同，可以互相检验 |
| 时段 | 非营业时段先建底图，营业时段补走一遍，用差异评估推车和人流的影响 |
| 姿态 | 手持看屏，与使用姿态一致 |
| 设备配置 | 统一不带磁吸壳、不装磁吸支架，写进 `meta.json` |
| 质检 | 每条通道走完当场检查（阶段 1.5），不合格当场重走 |

## 6. 风险与决策点

| 风险 | 影响 | 应对 | 在哪个门槛暴露 |
|---|---|---|---|
| **27 条长度相同的平行通道** | 认错通道，位置跳到隔壁 | 路网约束 + 长窗口序列 + 蓝牙先验 + 部门分区；可区分度热力图提前量化 | G0、G2 |

| 钢货架附近罗盘偏差 | 航向错 | 航向不用罗盘，用陀螺 + 曼哈顿先验 | G3 |
| 步长误差累积 | 序列匹配变形 | 在线学习步长，匹配时允许 ±10% 缩放 | G3 |
| 冷启动慢 | 用户等待久 | 蓝牙粗定位 / 用户点选起点 / 入口先验 | G3 |
| 推车干扰 | 精度下降 | 第一期只测手持；第 5 阶段单独评估并决定是否做专门模式 | G5 |
| 免费签名每 7 天过期 | 现场采集时 App 打不开 | 采集前一天重新签名一次；长期用 TestFlight | — |
